Power BI QA

Automated Power BI Data Validation Framework

Challenge: Business teams relied on Power BI dashboards for decisions, but regression testing was manual. Testers had to open each report, read KPI values, and compare them against warehouse queries one by one. The process took around two days per regression cycle across 30+ reports and left room for missed issues.

Role: QA Lead, framework design and team delivery.

Python Playwright Snowflake dbt SQL YAML CI/CD Claude Code
30+ reports validated in under 1 hour with repeatable, auditable output.

Approach

  • UI extraction using Playwright to read values shown to users such as KPI cards, chart category labels, and matrix/table rows.
  • Data reconciliation using SQL in Snowflake/dbt with the report’s specific “Data As Of” date to ensure comparisons never drift across refreshes.
  • Comparison logic with tolerance rules for single values, grouped charts, and full tables using composite keys.
  • Business-rule validation for missing values, duplicate keys, negative counts, and percentage totals that should sum to 100.
  • ETL-layer checks for missing keys, duplicate records, and null control fields before report validation even begins.
  • Pipeline execution across parallel CI agents that produce HTML, JSON, and Excel artifacts with screenshots and automatic SQL diagnostics on failure.

Why this mattered

Config over code

Adding a report meant adding YAML definitions and SQL files instead of adding new framework logic.

Fail loudly

When the “Data As Of” date or report data could not be resolved, the framework failed clearly instead of silently passing.

Layered validation

A browser pass only proves the report displayed a number; source reconciliation proved the number was correct.

AI as accelerator

Claude Code accelerated scaffolding and refactors, while human QA ownership remained in test strategy, SQL logic, and acceptance criteria.

Outcome

  • 30+ Power BI reports under automated regression validation.
  • Regression validation reduced from around two days to under one hour.
  • Results became repeatable, auditable, and easy to extend through configuration.
  • Quality checks covered both what users see and what the warehouse says.
